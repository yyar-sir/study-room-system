# 基于 SpringBoot 的共享自习室预约与管理系统

> 本科毕业设计项目 · Spring Boot 3 + Vue 3 前后端分离全栈实现

面向城市付费共享自习室的运营管理与用户预约服务，采用 **B/S 架构、前后端分离**，
覆盖 **三类角色**（自习室用户 / 前台管理员 / 自习室经营者）与
「选座预约 — 到店签到 — 权益计费 — 数据统计 — 智能问答」完整业务闭环。

---

## 一、技术栈

| 层 | 选型 |
|---|---|
| 后端 | Spring Boot 3.2.5 · Java 21 · MyBatis-Plus 3.5.7 · JJWT 0.12.6 · Spring Security Crypto(BCrypt) |
| 前端 | Vue 3.5 · Vue Router 4 · Element Plus 2.9 · ECharts 5 · Axios · Vite 6 |
| 数据库 | MySQL 8.4（utf8mb4 / utf8mb4_0900_ai_ci） |
| 大模型 | DeepSeek（OpenAI 兼容协议，JDK 内置 HttpClient，无额外 SDK） |

- Maven 3.9+（或使用 IDE 内置）
- Node.js 18+ 与 npm
- MySQL 8.0+（开发环境为 8.4）

## 三、快速开始

### 0. 环境装好之后，日常怎么启动（最常见的情况）

**关掉电脑再开机，只需双击项目根目录的 `start-all.bat`。** 它会依次：确认 MySQL
（它是一个开机自启的 Windows 服务，无需手动启动）→ 新窗口启动后端 → 新窗口启动前端
→ 自动打开浏览器。

**停止系统**：关掉标题为 `Study Room Backend (8080)` 与 `Study Room Frontend (5173)`
的两个窗口。**关掉启动器窗口不会停止它们。**

也可以分开手动启动（两个窗口各跑一个）：

| 双击 | 作用 | 地址 |
|---|---|---|
| `start-backend.bat` | 启动后端（约 10-15 秒） | http://127.0.0.1:8080 |
| `start-frontend.bat` | 启动前端 dev server | http://127.0.0.1:5173 |

> **必须先起后端再起前端**：前端 dev server 把 `/api` 代理到 8080。
>
> 两个 `.bat` 里都是**绝对定位**（用 `%~dp0` 相对脚本自身，`cd /d` 切目录），
> 所以放在哪、从哪双击都能跑。内容刻意写成纯 ASCII —— cmd 默认代码页是 GBK，
> 含中文的 `.bat` 显示会乱码。
>
> 这两个脚本只负责**运行**，不负责构建。若 `target/*.jar` 或 `node_modules` 缺失，
> 脚本会直接报错并告诉你该执行什么命令，不会静默失败。

### 1. 首次部署：建库与导入演示数据

```bash
mysql -u root -p --default-character-set=utf8mb4 < backend/sql/init.sql
mysql -u root -p --default-character-set=utf8mb4 < backend/sql/demo-data.sql
```

> `mysql` 客户端不在 PATH 里时，用绝对路径：
> `"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe"`。

> `init.sql` 只创建 `study_room` 库（`CREATE DATABASE IF NOT EXISTS`），**不含任何 DROP DATABASE**，
> 不会影响机器上已有的其它数据库。

> ⚠️ **三个 `.sql` 文件都带 UTF-8 BOM，请不要去掉。**
> 踩坑记录：无 BOM 时，Windows PowerShell 的 `Get-Content -Raw` 会按系统 ANSI
> （简体中文机器上是 GBK）解码，中文注释被解成乱码字节后会**吞掉换行**，
> 紧跟其后的语句就被并进注释里从而**静默跳过**——实测 `reset-demo.sql` 有 16 行被吞，
> `member_order` 与 `operation_log` 的清理整个消失，随后删用户时才报外键错误，
> 而报错行号还是错的，极难排查。MySQL 8 能正常接受开头的 BOM（`<` 重定向 /
> 管道 / `source` 三种方式均已实测）。

**演示数据重置**（答辩前建议执行一次）：

```bash
mysql -u root -p --default-character-set=utf8mb4 study_room < backend/sql/reset-demo.sql
```

该脚本清除预约/签到/流水/权益/订单/消息/违规/公告/操作日志等业务数据与测试账号，
把座位状态复原为初始值，并重算门店座位总数；**保留**门店、座位、座位类型、套餐、
知识库、营业时段、运营规则与三个演示账号。可重复执行。

> 账号清理用的是**白名单**（`phone NOT IN (三个演示号)`）而不是号码段匹配：
> 早先写成 `LIKE '136%' OR '137%'`，结果一个用 173 号段注册的测试账号留了下来。
>
> 重置后**演示用户没有生效中的套餐**——这不是故障，而是刻意的：
> 演示流程正好从「会员套餐 → 购买」开始，买完再选座、签到、扣次，能把链路走全。
> 若跳过购买直接去选座，页面会明确提示「你还没有可用的套餐权益」并给出购买入口
> （而不是显示一片点不动的灰座位）。
> 重置后**操作日志为空**也属正常：登录一次就会产生记录。

### 2. 配置后端

复制模板并填写本机信息（该文件已被 `.gitignore` 忽略，不会进仓库）：

```bash
cp backend/src/main/resources/application-local.yml.example \
   backend/src/main/resources/application-local.yml
```

需要填写的三项：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/study_room?...
    username: <你的数据库账号>
    password: <你的数据库口令>
jwt:
  secret: <至少 32 字符的随机串>     # 见下方「常见坑」
ai:
  api-key: <你的 DeepSeek API Key>   # 不填则 AI 助手走知识库降级路径，不影响其它功能
backup:
  dir: <备份文件目录>
  mysqldump: <mysqldump 可执行文件路径>
```

### 3. 启动

```bash
# 后端 → http://127.0.0.1:8080
cd backend && mvn spring-boot:run

# 前端 → http://127.0.0.1:5173（vite 已配置 /api 代理到 8080）
cd frontend && npm install && npm run dev
```

项目自带可重复执行的接口回归脚本，**166 项检查**，覆盖认证、越权、业务规则、降级、
公告推送、操作日志、营业时段与前台代取消：

> PowerShell 会按 GBK 解码，中文字符串被破坏并吞掉后续换行，脚本会**静默失效**
> （看起来在跑，实际大量断言没执行）。脚本开头有自检，会直接报错退出。

## 七、几个关键设计（答辩要点）

1. **权益走账本制，余额不按状态实时推导。** 消费流水表 `consumption_record` 上
   `(user_id, source_key)` 唯一约束充当幂等闸门；写入顺序是**先插流水、后改余额**——
   若反过来，一旦重复触发导致流水插入失败，余额已经被多扣且事务里补不回来。
2. **取消预约后可以重新预约同一时段。** 座位/日期/开始时间的唯一约束改用
   「生成列 + 唯一索引」：非生效状态取 NULL，而 MySQL 唯一索引视多个 NULL 互不相同，
   于是已取消/已完成/爽约的记录不再永久占用该时段。
3. **并发预约不超卖。** 预约时对座位行加悲观锁（`SELECT … FOR UPDATE`）串行化同一座位的并发请求；
   唯一索引只能拦住"开始时间完全相同"，拦不住 09:00-11:00 与 10:00-12:00 这类部分重叠。
4. **相邻时段不算冲突。** 重叠判定用严格不等号 `aStart < bEnd && aEnd > bStart`，
   使得 09:00-10:00 与 10:00-11:00 可以共存 —— 写成 `<=` 会把整点接续的排期全部拒掉。
5. **单次预约有最长时长限制。** 营业时间是 08:00-22:00，若只校验"在营业时间内"，
   用户可以一次预约 14 小时把座位整天锁死，其他人全天都约不到。
   上限由运营规则 `max_reserve_hours`（默认 4 小时）控制，比较用「严格大于」，
   正好等于上限的预约必须放行。规则通过 `/api/public/rules` 下发给前端展示，
   前端不硬编码，避免改了后台配置前后端不一致。
6. **大模型是不可靠外部依赖。** AI 助手实现三级降级：正常调用 → 知识库兜底 →
   场景化文案，接口层永不抛未处理异常；并带按用户限流、内容安全过滤与密钥脱敏。
7. **权限分两层且数据范围在服务端强制。** 拦截器只管"有没有登录"，`@RequireRole`
   管"这个角色能不能调"；前台的门店数据范围由后端按 `storeId` 过滤，
   不依赖前端隐藏菜单。
8. **深色主题靠 CSS 变量整体翻转，不给每个页面写第二套样式。** 所有颜色都收在
   `main.css` 的 `:root`，深色只需一个 `html[data-theme="dark"]` 覆盖块。两个坑：
   ① 必须**同时**写 `<html data-theme="dark">`（我们自己的变量）和 `<html class="dark">`
   （Element Plus 的暗色变量），少一个就会出现"卡片变深了、表格还是白的"；
   ② `--brand-deep` 原本既当"强调文字色"又当"按钮 hover 底色"，深色下前者要变亮、
   后者要变暗，一个变量扛不了两种角色，因此拆出 `--brand-hover` / `--accent-hover`。
9. **操作日志走 AOP 统一拦截，且必须先有"读"的出口。** 用切面而不是在每个 Service
   里手写记日志：前者不可能漏。三条约束：①只记写操作（GET 不记，否则看板一进页面
   就打 7 个统计请求，日志表会被读操作淹没）；②**请求参数里的口令类字段必须脱敏**
   （否则等于把明文口令又存了一份，比不加日志更糟）；③记日志失败绝不上抛，
   不能让日志表写不进去导致用户预约失败。
10. **营业时段用「可预约时段的并集完整覆盖」判定，而不是"落在单个时段内"。**
    门店常把一天切成 08-12 / 12-18 / 18-22 三段，此时 11:00-13:00 这种跨段预约是
    正常的；要求落在单段内会误拒。而 `bookable=0` 的闭馆段不参与并集，于是自然形成
    空洞，"午休 12:00-13:00 不可预约"就是这样表达的。未配置任何时段时直接放行并
    回落到 `store.open_time/close_time`，保证本功能在经营者配置之前不改变既有行为。
11. **定时任务的幂等要按"业务实体"做，不能按"时间窗"做。** 预约开始提醒每 5 分钟
    跑一次而提醒窗口有 30 分钟，同一笔预约会被扫到约 6 次；这里把预约 id 编进
    `notification.link` 做精确匹配。若像套餐到期提醒那样用"24 小时内是否提醒过"
    的时间窗判断，会把用户当天的第二笔预约提醒一起吞掉。
12. **前台代取消刻意不受"取消时限"约束。** 用户自助取消有"距开始不足 N 分钟不许取消"
    的限制，那是防用户临开场放鸽子；而前台处理的恰恰是异常场景（用户来电说来不了、
    座位故障需换位），此时照搬用户规则只会让前台无计可施。差别不写在文档里而写在
    `cancelByStaff` 上：它同时要求**必须填原因**并把操作人写进 `cancel_reason`，
    再给用户发一条站内通知——预约是被别人取消的，不告知用户只会到店后才发现。
13. **只增不减的表必须配保留策略。** `ai_chat_record`（每次提问写两条）与
    `operation_log`（每次写操作写一条）都会持续堆积并拖慢备份。清理周期走运营规则
    配置，**配成 0 表示不清理**——审计要求高的场景把操作日志设为永久保留即可，
    不必改代码。两张表默认值不同：对话 30 天（只是体验功能），操作日志 90 天（审计依据）。
14. **对比度必须用「计算后样式」逐元素核，不能靠看代码。** 登录页标题曾经是**不可见的**
    （深蓝 `#1c2740` 压在深蓝 `#15285c` 上，1.05:1），但读代码看不出来——它是被一条
    全局 `h1 { color: var(--ink) }` 直接命中、压掉了从 `.brand-side` 继承来的白色。
    这类问题只有把 DOM 的实际前景/背景色算出来才会暴露。项目里放了一个 CDP 审计脚本
    （`shots/contrast-audit.mjs`），遍历 22 个页面 × 深浅两套主题逐元素算对比度，
    按 WCAG AA 判定（正文 4.5:1、大字号 3:1），并**按「标签+类名」去重**避免表格
    逐行重复计算。首轮查出浅色 68 处、深色 7 处不达标，归因后其实只有 6 个根因：
    `--ink-3` 过浅（约 60 处）、EP 的 `--el-text-color-secondary` / `--el-color-info`
    两次漏映射、`--accent-deep` / `--warn-fg` / `--yellow-fg` 偏浅、以及
    **`--brand` 同时被当作背景与文字**（深色下当文字需 L≥0.210、当背景需 L≤0.183，
    数学上无解，因此拆出 `--brand-ink`）。修完复测两套主题均为 0 处。
    另外，禁用态与 emoji 图标在脚本里被显式排除——WCAG 对非活动组件豁免，
    而 emoji 由字体自带颜色渲染、拿 CSS `color` 去算必然是误报。

## 九、安全约定

- 数据库口令、JWT 密钥、大模型 API Key 一律只存在于 `application-local.yml`
  （已被 `.gitignore` 忽略），禁止提交进仓库。
- 口令使用 **BCrypt** 加盐散列存储，绝不用 MD5/明文；散列字段带 `@JsonIgnore`，
  任何接口都不会下发。
- JWT 为无状态令牌、签发后无法撤销，因此改密/重置密码会写入
  `password_changed_at`，拦截器据此拒绝此前签发的所有 token（等价于"改密即踢下线所有设备"）。
